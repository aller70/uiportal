# Техническое задание на разработку корпоративного интранет-портала

## 1. Общие сведения

### 1.1. Наименование системы

Корпоративный интранет-портал (далее — Портал).

### 1.2. Назначение и цели создания системы

**Назначение:** Создание единого информационного и сервисного пространства для сотрудников компании.

**Цели:**

* Информирование сотрудников о новостях, событиях и корпоративной жизни компании (включая публикацию фотоотчетов с мероприятий), а также оперативная доставка системных и персональных уведомлений.

* Предоставление быстрого доступа к справочной информации о сотрудниках и организационной структуре.

* Автоматизация и упрощение доступа к внутренним корпоративным сервисам (подача и согласование заявлений на отпуск по иерархии с интеграцией в 1С, бронирование переговорных, питание и др.).

* Централизованное хранение и ознакомление с нормативной документацией (охрана труда, ИБ, зарплатный проект).

* Предоставление Администраторам централизованного инструмента для мониторинга, настройки, аудита, управления учетными данными внешних коннекторов и администрирования всех подсистем Портала.

## 2. Требования к архитектуре и технологическому стеку

Портал должен быть реализован как современное веб-приложение (Single Page Application / Server-Side Rendering) с использованием микросервисной или модульной монолитной архитектуры.

* **Frontend:** React (Next.js) или Vue.js (Nuxt.js), TypeScript, Tailwind CSS / Ant Design / Material UI. Адаптивная верстка (Desktop-first с поддержкой мобильных устройств).

* **Backend:** Node.js (NestJS) / Python (FastAPI / Django) / C# (.NET 8) или Go. Архитектура API — RESTful или GraphQL.

* **Real-time коммуникации:** WebSockets (Socket.io / SignalR) или Server-Sent Events (SSE) для мгновенной доставки оповещений, персональных сообщений и телеметрии в админ-панель без перезагрузки страницы.

* **База данных и хранилище медиа:** PostgreSQL (основное хранилище данных портала, включая расписание переговорных, заявки на отпуск, зашифрованные конфигурации коннекторов, логи аудита и историю сообщений), Redis (кэширование сессий, брокеринг сообщений и очередей уведомлений), S3-совместимое объектное хранилище (MinIO / Ceph) для хранения фотографий галереи и документов.

* **Поисковый движок:** Elasticsearch или OpenSearch (для быстрого сквозного поиска по сотрудникам, новостям, фотоальбомам, документам и системным логам).

* **Контейнеризация и инфраструктура:** Docker, Kubernetes / Docker Compose, Nginx (Reverse Proxy), Prometheus + Grafana (или встроенный модуль метрик для дашборда Администратора).

## 3. Аутентификация, авторизация и ролевая модель

### 3.1. Интеграция с Active Directory (AD) и SSO

* Источником учетных записей, базовых данных о пользователях и иерархии подчинения (атрибут `manager` или структура подразделений) является корпоративный каталог Active Directory (LDAP) в связке с данными организационной структуры из 1С.

* Авторизация на Портале должна осуществляться прозрачно для пользователя с использованием технологии **Single Sign-On (SSO)** на базе протоколов Kerberos / NTLM или SAML 2.0 / OpenID Connect (через ADFS / Keycloak).

* Параметры подключения к контроллерам домена AD, учетные данные сервисных аккаунтов (Bind DN) и настройки SSO-провайдера должны конфигурироваться Администратором непосредственно через веб-интерфейс Центра управления порталом без необходимости перезапуска серверных контейнеров или ручного редактирования конфигурационных файлов.

* Синхронизация данных пользователей из AD должна происходить автоматически по расписанию (например, раз в сутки или каждые 2 часа), а также принудительно по запросу Администратора из Центра управления.

### 3.2. Ролевая модель (RBAC) и функциональные полномочия

Каждому пользователю в системе назначается одна из трех базовых системных ролей (вручную через Центр управления или автоматически на основе сопоставления с группами безопасности AD):

| Роль | Описание прав доступа | 
| ----- | ----- | 
| **Читатель** *(по умолчанию)* | Просмотр всех опубликованных разделов портала и персонального дашборда, просмотр и скачивание фотографий из «Фотогалереи», использование поиска, получение оповещений и персональных сообщений, просмотр своих данных по отпускам, создание и отправка на согласование заявлений на отпуск, создание/редактирование/отмена собственных броней переговорных комнат, скачивание документов. | 
| **Редактор** | Все права «Читателя» + создание, редактирование и удаление контента в разделах: «Новости», «Фотогалерея» (создание альбомов и пакетная загрузка фото), «Меню кафе», «Меню ресторана», обновление справочной информации в разделе «Общие сервисы» (зарплатный проект, охрана труда, ИБ). Включает полномочия **Редактора переговорных** (управление фондом переговорных комнат, их расписанием и модерация броней пользователей). | 
| **Администратор** | Полный доступ ко всем функциям Портала и выделенному **Центру управления порталом** (с административным дашбордом). Управление пользователями, ролями и маппингом групп AD, настройка учетных данных для доступа к AD, внешних серверов и системных коннекторов (1С, SMTP, S3, SSO), мониторинг и ручной запуск синхронизации с AD и 1С, гибкая настройка маршрутов согласования отпусков, управление справочниками и переговорными, отправка глобальных системных оповещений, просмотр журналов аудита и аналитики. | 

*Примечание по процессу согласования:* Пользователям, являющимся руководителями подразделений согласно организационной иерархии (независимо от их базовой роли — Читатель, Редактор или Администратор), автоматически открывается функционал согласования заявлений на отпуск их прямых и нижестоящих подчиненных.

## 4. Функциональные требования по разделам и подсистемам

### 4.1. Главная страница (Пользовательский дашборд)

Главная страница представляет собой интерактивный модульный дашборд сотрудника, агрегирующий ключевую информацию и персональные показатели из всех разделов Портала:

* **Глобальная шапка (Header):** сквозная строка живого поиска по всему Порталу, индикатор непрочитанных оповещений («колокольчик»), иконка личных сообщений со счетчиком, мини-профиль текущего пользователя и кнопка перехода в «Центр управления» (отображается только для Администраторов).

* **Персональный сервисный виджет («Мой статус и задачи»):**

  * Остаток дней отпуска в текущем году, статус активного заявления на отпуск и кнопка быстрой подачи новой заявки.

  * **Для руководителей:** счетчик заявлений подчиненных, ожидающих согласования («Требуют вашего решения: $N$»), с быстрым переходом к рассмотрению.

  * Ближайшие бронирования переговорных комнат на сегодня с участием текущего сотрудника (время, комната, тема) и кнопка «Забронировать переговорную».

* **Блок главных и последних новостей:** карусель закрепленных важных новостей и лента последних публикаций компании.

* **Виджет «Дни рождения сегодня»:** карточки сегодняшних именинников с кнопкой отправки поздравления в личные сообщения в 1 клик.

* **Виджет «Меню на сегодня»:** компактный блок с переключением вкладок «Кафе» / «Ресторан» (отображение бизнес-ланча или блюд дня).

* **Виджет «Свежие фотоотчеты»:** превью последних опубликованных альбомов из корпоративной фотогалереи.

* **Блок «Быстрые ссылки и сервисы»:** плитка иконок для мгновенного перехода к корпоративному файловому хранилищу, документам по охране труда, ИБ и зарплатному проекту.

* **Персонализация:** возможность для пользователя сворачивать отдельные неиспользуемые виджеты или менять их взаимное расположение (опционально).

### 4.2. Раздел «Новости»

* **Для Читателя:**

  * Лента новостей с пагинацией или бесконечным скроллом.

  * Фильтрация по тегам/рубрикам и дате публикации.

  * Карточка новости: заголовок, дата, обложка, краткое описание, полный текст (с поддержкой форматирования, фото, видео, вложений и прикрепления ссылки/виджета альбома из раздела «Фотогалерея»), счетчик просмотров.

* **Для Редактора / Администратора:**

  * WYSIWYG-редактор для создания и форматирования новостей.

  * Возможность сохранения в черновики, отложенной публикации (по таймеру), закрепления важной новости вверху ленты и принудительной отправки push-оповещения сотрудникам о выходе критически важной новости.

### 4.3. Раздел «Меню кафе»

* Отображение меню на текущий день и на текущую неделю (переключение по дням недели).

* Категории блюд (Завтраки, Салаты, Супы, Горячее, Гарниры, Напитки, Выпечка).

* Карточка блюда содержит: название, состав/описание, выход (вес в граммах), КБЖУ (опционально), цену.

* **Для Редактора:** удобный интерфейс загрузки меню (ручной ввод или импорт из шаблона Excel/CSV), а также возможность загрузки скан-копии/PDF меню.

### 4.4. Раздел «Меню ресторана»

* Аналогичен по структуре разделу «Меню кафе», но адаптирован под концепцию корпоративного ресторана (например, раздел с бизнес-ланчами и основное меню A la carte).

* Возможность публикации специальных сезонных предложений.

* **Для Редактора:** функционал управления позициями меню и импорта из Excel/CSV.

### 4.5. Раздел «Сотрудники» (Адресная книга и Оргструктура)

* **Иерархия подразделений:** отображение в виде интерактивного дерева (оргструктуры) с выделением руководителя каждого подразделения. При клике на подразделение выводится список входящих в него сотрудников и дочерних отделов.

* **Поиск и фильтрация:** живой поиск по ФИО, должности, внутреннему телефону, кабинету, подразделению.

* **Карточка сотрудника (персональная информация):**

  * Фотография (с заглушкой при отсутствии).

  * ФИО.

  * Должность.

  * Подразделение (с кликабельным путем в иерархии) и ФИО непосредственного руководителя.

  * Внутренний (добавочный) телефон и корпоративный мобильный (при наличии).

  * Email (кликабельная ссылка `mailto:`) и кнопка **«Написать сообщение»** (для отправки личного сообщения внутри Портала).

  * Местоположение: Здание, Кабинет/Этаж.

  * Дата рождения (только **день и месяц**, без указания года).

  * Статус присутствия (например, бейдж «В отпуске» с указанием дат и замещающего сотрудника, получаемый на основе данных из 1С / утвержденных заявок).

### 4.6. Раздел «Дни рождения»

* **Блок «Именинники сегодня»:** выделенный блок в верхней части страницы с карточками сотрудников, у которых день рождения совпадает с текущей датой, и кнопкой быстрой отправки поздравления в личные сообщения на Портале.

* **Календарь / Список дней рождения:**

  * Отображение списка сотрудников с фильтрацией по месяцам (по умолчанию — текущий месяц, отсортированный по числам).

  * Отображение краткой карточки: Фото, ФИО, Должность, Подразделение, Дата рождения (день и месяц).

### 4.7. Раздел «Отпуска» (Интеграция с 1С и согласование по иерархии)

Раздел объединяет персональную статистику по отпускам из 1С и электронный документооборот по подаче и согласованию заявлений на отпуск непосредственно на Портале.

* **Механизм двусторонней интеграции с 1С (1С:ЗУП / 1С:ERP):**

  * Взаимодействие осуществляется посредством опубликованного на стороне 1С HTTP-сервиса (REST API в формате JSON) или OData.

  * Связка учетной записи сотрудника на Портале (AD) с физическим лицом/сотрудником в 1С производится по уникальному идентификатору (Табельный номер, Email или GUID/СНИЛС).

  * **Из 1С на Портал** передаются: актуальный остаток дней отпуска, утвержденный годовой график отпусков, история использованных отпусков и штатная иерархия руководителей.

  * **С Портала в 1С** автоматически передаются полностью согласованные по иерархии заявления на отпуск для создания кадрового документа в 1С и последующего расчета.

* **Отображаемая информация для сотрудника:**

  * Виджет с крупным отображением **остатка доступных дней отпуска в текущем году** (с разбивкой на основной, дополнительный отпуск и зарезервированные дни по заявкам на согласовании).

  * Таблица утвержденного графика отпусков и истории отпусков за текущий год.

  * Список поданных заявлений с текущим статусом и визуализацией этапа согласования («Черновик», «На согласовании у непосредственного руководителя», «На согласовании у вышестоящего руководителя», «Согласовано / Передано в 1С», «Оформлено в 1С», «Отклонено»).

* **Подача заявления на отпуск сотрудником:**

  * Интерактивная форма создания заявки: выбор вида отпуска (ежегодный оплачиваемый, без сохранения заработной платы, учебный и др.), выбор дат начала и окончания (с автоматическим подсчетом календарных дней с учетом производственного календаря РФ), выбор замещающего сотрудника на период отсутствия, комментарий.

  * Автоматический контроль на стороне Портала: проверка достаточности остатка дней отпуска и предупреждение при нарушении правил (например, подача менее чем за 14 дней).

* **Процесс согласования руководителями по иерархии:**

  * При отправке заявления Портал автоматически выстраивает маршрут согласования вверх по организационной иерархии сотрудника (Непосредственный руководитель отдела $\rightarrow$ Руководитель департамента/направления $\rightarrow$ HR/Кадровая служба в 1С). Глубина иерархии настраивается Администратором (например, 1 или 2 уровня руководителей).

  * У руководителей в разделе «Отпуска» доступна вкладка **«На согласовании»** (а также календарь пересечений отпусков сотрудников их подразделения для оценки нагрузки).

  * Руководитель получает мгновенное оповещение на Портале и по Email о новой заявке и может прямо из интерфейса Портала:

    * **Согласовать** заявление (заявка автоматически переходит на следующий уровень иерархии или отправляется по API в 1С, если руководитель финальный).

    * **Отклонить** заявление или отправить на доработку (с обязательным указанием причины в комментарии; сотрудник получает уведомление об отказе).

  * Поддержка делегирования полномочий согласования на другого сотрудника на время отпуска самого руководителя.

### 4.8. Раздел «Общие сервисы»

Представляет собой хаб с подразделами и интерактивными модулями:

1. **Бронирование переговорных комнат (Собственный модуль Портала):**

   * Управление переговорными комнатами и их расписанием осуществляется **целиком внутри Портала** на базе собственной базы данных.

   * **Функционал для Администратора и Редактора переговорных (Управление фондом и модерация):**

     * Создание, редактирование и удаление (архивация) карточек переговорных комнат.

     * Настройка параметров каждой переговорной: название, здание, этаж, номер кабинета, вместимость (кол-во человек), фото, доступное оборудование (ВКС, ТВ/проектор, флипчарт, маркерная доска), допустимое рабочее время для бронирования, признак «Требует подтверждения Редактором» (для VIP-переговорных или конференц-залов).

     * Управление расписанием и модерация: возможность временно заблокировать переговорную (на время ремонта или спецмероприятия), подтверждать/отклонять заявки в модерируемых комнатах, а также переносить, редактировать или принудительно отменять любые брони пользователей (с автоматической отправкой уведомления организатору о причине изменений).

   * **Функционал для Пользователей (Читатель / Редактор):**

     * Интерактивная сетка-календарь (режимы просмотра: «День», «Неделя», «Месяц») со списком переговорных и визуализацией занятых/свободных слотов.

     * Фильтрация переговорных по зданию, этажу, минимальной вместимости и необходимому оборудованию, а также поиск свободной комнаты на заданный временной интервал.

     * Создание бронирования в свободный слот с указанием: темы встречи, описания/повестки, времени начала и окончания, списка участников (выбор сотрудников из справочника Портала).

     * Поддержка создания регулярных (повторяющихся) встреч (ежедневно, еженедельно в выбранные дни).

     * Автоматический контроль коллизий на уровне бэкенда Портала (запрет наложения броней в одной комнате).

     * Просмотр деталей чужой брони в сетке календаря (кто забронировал, его внутренний телефон, тема встречи).

     * Управление своими бронями: раздел «Мои бронирования» с возможностью переноса времени, изменения списка участников или отмены встречи.

     * Автоматическая рассылка оповещений внутри Портала и по Email (с вложением `.ics`) всем участникам при создании, изменении или отмене встречи.

2. **Корпоративное файловое хранилище:**

   * Выделенный блок/кнопка с прямой ссылкой на сетевое хранилище (Nextcloud / SharePoint / сетевая папка `file://` или веб-интерфейс хранилища) и краткой инструкцией по подключению сетевых дисков.

3. **Зарплатный проект:**

   * Информационная страница с описанием условий обслуживающих банков, привилегий для сотрудников, контактами персональных менеджеров и шаблонами заявлений на смену реквизитов.

4. **Охрана труда:**

   * Каталог нормативных документов, инструкций, приказов и памяток с возможностью предпросмотра (PDF) и скачивания.

5. **Информационная безопасность (ИБ):**

   * Раздел с политиками ИБ, регламентами, инструкциями по работе с паролями/VPN, а также кнопкой/контактами для оперативного сообщения об инцидентах безопасности (фишинг и т.д.).

### 4.9. Раздел «Фотогалерея» (Фотографии с корпоративных мероприятий)

Раздел предназначен для публикации и просмотра фотоотчетов с корпоративных праздников, конференций, тимбилдингов и спортивных событий компании.

* **Для Читателя:**

  * **Витрина альбомов:** отображение карточек фотоальбомов в виде сетки. Каждая карточка содержит обложку альбома, название мероприятия, дату проведения, количество фотографий и счетчик просмотров.

  * **Фильтрация и поиск:** фильтрация альбомов по году, тегам/категориям мероприятий (Праздники, Спорт, Конференции, Офисная жизнь) и поиск по названию события.

  * **Страница альбома и просмотр фотографий:**

    * Адаптивная сетка превью фотографий (Masonry-раскладка или плитка) с отложенной загрузкой (lazy loading) по мере прокрутки страницы.

    * Полноэкранный режим просмотра (Lightbox-галерея) с поддержкой перелистывания (стрелками клавиатуры, мышью или свайпами), масштабирования (зума) и запуска слайд-шоу.

    * Интерактивные функции: возможность поставить отметку «Нравится» (лайк) на отдельные фотографии или альбом в целом.

    * **Скачивание:** возможность скачать как отдельную фотографию в оригинальном высоком разрешении, так и весь альбом целиком (в виде автоматически сформированного `.zip`-архива).

* **Для Редактора / Администратора:**

  * Создание и редактирование альбомов: указание названия, даты проведения мероприятия, краткого описания, тегов и выбор главной обложки альбома.

  * Пакетная (массовая) загрузка фотографий (Drag-and-Drop до 200–500 снимков за один раз) с отображением индикатора прогресса загрузки.

  * **Автоматическая обработка на стороне сервера:** при загрузке оригиналов в высоком разрешении система автоматически генерирует облегченные миниатюры (thumbnails) и оптимизированные веб-копии в формате WebP для быстрой загрузки страниц без потери качества оригиналов.

  * Управление содержимым альбома: изменение порядка сортировки фотографий, поворот снимков, удаление отдельных неудачных кадров, скрытие альбома в черновики.

### 4.10. Подсистема оповещений и персональных сообщений пользователям

Для обеспечения оперативной коммуникации и информирования о событиях на Портале реализуется единый коммуникационный модуль, доступный с любой страницы из верхней панели навигации:

1. **Системные и сервисные оповещения (Центр уведомлений — «Колокольчик»):**

   * Всплывающие уведомления (toast-нотификации) в реальном времени (через WebSockets/SSE) и выпадающий список со счетчиком непрочитанных событий.

   * **Типы оповещений для текущего пользователя:**

     * *По отпускам:* поступление нового заявления на согласование от подчиненного (с быстрыми кнопками «Перейти к согласованию»); изменение статуса собственного заявления на отпуск (согласовано руководителем, отклонено с комментарием, проведено в 1С); напоминание о приближающемся плановом отпуске за 2 недели.

     * *По переговорным комнатам:* приглашение на встречу от другого сотрудника; изменение времени/места или отмена встречи организатором либо Редактором переговорных; напоминание за 15 минут до начала забронированной встречи.

     * *Общекорпоративные:* публикация важной новости с отметкой «Срочно/Важно», публикация нового фотоальбома с корпоративного мероприятия (по выбору Редактора), системные объявления от Администратора.

   * Функционал управления: отметка «Прочитано» (по одному или «Прочитать все»), фильтрация на «Все» и «Непрочитанные», переход к целевому объекту (заявке на отпуск, брони в календаре, новости, фотоальбому) по клику на уведомление.

   * Дублирование критически важных оповещений (заявки на согласование отпуска, изменения броней) на корпоративный Email пользователя.

2. **Персональные сообщения текущему пользователю (Внутренний мессенджер / Инбокс):**

   * Раздел личных сообщений (диалогов) между сотрудниками компании, доступный через иконку «Сообщения» в шапке Портала или по кнопке «Написать сообщение» в карточке сотрудника / блоке «Именинники».

   * Возможность отправки текстовых сообщений, эмодзи (например, для быстрых поздравлений с днем рождения), ссылок на внутренние разделы/документы/фотографии Портала и прикрепления файлов.

   * Отображение индикатора новых непрочитанных сообщений, статуса прочтения сообщения собеседником и истории переписки с поиском по тексту и сотрудникам.

   * Возможность отправки адресных сервисных сообщений конкретному пользователю от имени Администратора или Редактора (например, уточнение по заявке или бронированию переговорной).

### 4.11. Центр управления порталом (Админ-панель) и Административный дашборд

Для пользователей с ролью **Администратор** предусматривается выделенный защищенный раздел — «Центр управления порталом», обеспечивающий полный контроль над работоспособностью, конфигурацией серверов, коннекторами, учетными данными, пользователями и контентом системы.

1. **Административный дашборд (Главный экран Центра управления):**

   Сводная панель мониторинга в реальном времени, включающая следующие аналитические и технические виджеты:

   * **Состояние системы и инфраструктуры (Health Check):** индикаторы доступности узлов (API-бэкенд, PostgreSQL, Redis, Elasticsearch, S3-хранилище, SMTP-сервер, WebSocket-сервер), утилизация дискового пространства в S3 (под фотогалерею и документы), время отклика API.

   * **Статус внешних коннекторов и интеграций (AD, SSO, 1С):** время последней успешной синхронизации с контроллерами домена Active Directory и сервером 1С, статус активности каждого коннектора (Online / Degraded / Ошибка авторизации), количество синхронизированных учетных записей и счетчик ошибок маппинга (например, сотрудники из AD, не найденные в 1С).

   * **Метрики активности пользователей:** количество активных пользователей онлайн в текущий момент (по данным WebSocket-сессий), посещаемость за сутки/неделю/месяц (DAU/MAU), топ популярных разделов, новостей и фотоальбомов.

   * **Операционная сводка по сервисам:**

     * *Отпуска:* количество заявок в статусе «На согласовании», количество успешно переданных в 1С заявок за месяц, индикатор «зависших» заявок (без движения у руководителя более $N$ дней) и счетчик ошибок при выгрузке в 1С.

     * *Переговорные комнаты:* общая загрузка переговорного фонда (в $\%$), количество активных броней на сегодня и заявок, ожидающих модерации Редактором переговорных.

2. **Управление пользователями, ролями и правами доступа:**

   * Реестр всех пользователей Портала с фильтрацией по роли, подразделению, статусу учетной записи (Активен / Заблокирован в AD) и статусу привязки к 1С.

   * Ручное назначение и отзыв ролей («Читатель», «Редактор», «Администратор»), а также наделение пользователей специальными полномочиями **Редактора переговорных**.

   * Настройка автоматического маппинга ролей Портала на группы безопасности Active Directory (например, группа `AD_Portal_Editors` $\rightarrow$ роль «Редактор»).

   * Функция принудительного завершения активных сессий пользователя и возможность ручной корректировки связки профиля AD с физическим лицом в 1С (при расхождении идентификаторов).

3. **Управление серверами, коннекторами и учетными данными (AD, SSO, 1С, Инфраструктура):**

   Выделенный подраздел для централизованной настройки сетевых подключений, управления сервисными учетными записями (Credentials Manager) и параметрами коннекторов в режиме реального времени:

   * **Коннектор к Active Directory (LDAP / LDAPS):**

     * Управление списком серверов — контроллеров домена (указание основного и резервных адресов Host/IP, портов $389$/$636$, настройка приоритетов переключения при отказе — failover).

     * Настройка учетных данных для подключения к AD: ввод сервисной учетной записи (**Bind DN / Логин** и **Пароль**), выбор режима шифрования (LDAPS / StartTLS) и загрузка корневых SSL/TLS-сертификатов центра сертификации предприятия.

     * Конфигурация параметров поиска и схемы каталога: указание базовых веток поиска пользователей и групп (`Base DN`, `Search OU`), кастомных LDAP-фильтров (например, отбор только активных сотрудников) и визуальный **маппинг атрибутов AD** на поля карточки сотрудника Портала (ФИО, должность, отдел, кабинет, внутренний телефон, `manager`, `thumbnailPhoto`).

     * Кнопка **«Проверить подключение к AD»** (Test Connection) для мгновенной валидации сетевой доступности контроллера домена, корректности учетных данных и тестового чтения одной записи из каталога.

   * **Коннектор SSO-аутентификации (Kerberos / SAML 2.0 / OIDC):**

     * Настройка параметров провайдера идентификации (ADFS / Keycloak / Windows Authentication): ввод `Entity ID`, `Metadata URL`, `Redirect URI`, управление `Client ID` / `Client Secret`, загрузка `.keytab`-файлов или X.509 сертификатов подписи токенов.

   * **Коннектор к серверу 1С (1С:ЗУП / 1С:ERP):**

     * Настройка адреса публикации информационной базы 1С (Endpoint URL для REST HTTP-сервиса или OData), выбор типа аутентификации (Basic Auth, Bearer Token / API-ключ) и ввод логина/пароля сервисного пользователя 1С.

     * Настройка сетевых таймаутов, лимитов запросов и количества автоматических повторных попыток (retry policy) при временной недоступности сервера 1С.

     * Кнопка **«Проверить соединение с 1С»** (выполнение пинг-запроса к сервису 1С с проверкой авторизации).

   * **Инфраструктурные серверы и сервисные коннекторы (SMTP и S3-хранилище):**

     * **Почтовый коннектор (SMTP):** настройка адреса почтового сервера (MS Exchange / Postfix), порта, шифрования (SSL/TLS), учетных данных отправителя (логин, пароль, адрес `From`) и кнопка отправки тестового письма текущему Администратору.

     * **Коннектор к S3-хранилищу медиафайлов:** настройка Endpoint URL сервера (MinIO / Ceph), имени корзины (`Bucket Name`), региона и ключей доступа (`Access Key ID` и `Secret Access Key`) с проверкой прав на запись/чтение.

   * **Безопасность хранения учетных данных:** все пароли, секретные ключи и токены коннекторов никогда не отображаются в открытом виде после сохранения (маскируются символами `••••••••`) и сохраняются в базе данных исключительно в зашифрованном виде (алгоритм AES-256-GCM с использованием мастер-ключа окружения или интеграцией с HashiCorp Vault).

4. **Диспетчер синхронизации и журналы обмена данными:**

   * Настройка расписания фоновых задач синхронизации для каждого коннектора (интервалы или cron-выражения) и кнопки **принудительного ручного запуска** синхронизации пользователей из AD или остатков отпусков из 1С.

   * Детальный лог обмена данными коннекторов с возможностью просмотра статуса операций, времени выполнения, тела ошибочных запросов (payload) и кнопкой повторной отправки (retry) зависших заявлений на отпуск в 1С.

5. **Конструктор маршрутов согласования отпусков и бизнес-правил:**

   * Настройка глубины иерархии согласования (например, 1 уровень — только непосредственный руководитель, 2 уровня — руководитель отдела + директор департамента) как глобально для компании, так и индивидуально для отдельных подразделений.

   * Управление правилами замещения (делегирования): возможность Администратору вручную назначить исполняющего обязанности (И.О.) руководителя на случай внезапного отсутствия согласующего лица, а также принудительно перенаправить заявку на другой этап.

   * Управление производственным календарем РФ и параметрами контроля (например, минимальный срок подачи заявления до начала отпуска).

6. **Управление глобальными справочниками и параметрами модулей:**

   * Ведение справочников зданий, этажей, типов оборудования переговорных комнат, рубрик/тегов новостей и категорий корпоративных мероприятий для «Фотогалереи».

   * Управление структурой навигационного меню Портала и глобальными ссылками (например, изменение URL корпоративного файлового хранилища).

   * Управление квотами на размер загружаемых файлов и параметрами сжатия изображений WebP для «Фотогалереи».

7. **Центр широковещательных рассылок и системных баннеров:**

   * Инструмент создания глобальных системных оповещений (push-уведомлений в «колокольчик» всем сотрудникам или выбранным подразделениям) и сквозных информационных баннеров в шапке Портала (например, предупреждение о плановых техработах или важных общекорпоративных событиях).

8. **Журнал аудита и безопасности (Audit Log):**

   * Неизменяемый реестр всех значимых действий в системе с фильтрацией по дате, пользователю, IP-адресу и типу события: входы в систему, изменение ролей, **изменение настроек серверов, коннекторов и учетных данных AD/1С**, публикация/удаление контента Редакторами, принудительная отмена броней переговорных, все этапы согласования/отклонения заявлений на отпуск.

   * Возможность экспорта журналов аудита в форматах CSV/Excel или передачи во внешнюю SIEM-систему.

## 5. Нефункциональные требования

### 5.1. Производительность и надежность

* Время отклика страниц портала и пользовательского дашборда при стандартной нагрузке не должно превышать $1.5$ сек. Доставка real-time оповещений и сообщений — не более $1$ сек.

* Оптимизация медиаконтента: использование ленивой загрузки (lazy loading) и автоматической конвертации превью изображений в формат WebP для быстрой отрисовки раздела «Фотогалерея».

* Система должна выдерживать одновременную работу до $N$ пользователей (уточняется на этапе проектирования, ориентировочно — до $100\%$ штата компании в пиковые утренние часы).

* Доступность системы (SLA) — не менее $99.5\%$ в рабочее время. Поддержка автоматического переключения на резервный контроллер домена AD при недоступности основного сервера.

### 5.2. Безопасность

* Доступ к Порталу возможен только из внутренней корпоративной сети (или через корпоративный VPN).

* Работа исключительно по защищенному протоколу HTTPS (TLS 1.2 / 1.3), WSS (для WebSockets) и LDAPS (для взаимодействия с контроллерами домена AD).

* Строгое разграничение прав доступа на уровне API: проверка полномочий руководителя при попытке просмотра или согласования чужих заявок на отпуск, защита личных сообщений от чтения третьими лицами, изоляция эндпоинтов Центра управления исключительно для роли «Администратор».

* Защита учетных данных коннекторов: хранение паролей сервисных учетных записей (AD Bind DN, 1С, SMTP, S3 Secret Keys) в базе данных строго в зашифрованном виде (AES-256) или в защищенном хранилище секретов (Vault); запрет на возврат сохраненных паролей в ответах API фронтенду.

* Защита от основных веб-уязвимостей (OWASP Top 10: XSS, CSRF, SQL-инъекции, LDAP-инъекции).

* Логирование всех действий пользователей с ролями «Редактор» и «Администратор» (включая любые модификации параметров подключения к серверам и коннекторам), а также всех операций согласования/отклонения заявлений на отпуск (аудит действий).

### 5.3. Требования к дизайну (UI/UX)

* Дизайн должен быть выполнен в соответствии с корпоративным брендбуком компании (логотип, фирменные цвета, шрифты).

* Интуитивно понятная навигация (боковое или верхнее меню, «хлебные крошки», фиксированная панель уведомлений и сообщений в шапке).

* Интерфейс Центра управления порталом должен обеспечивать высокую плотность данных (удобные таблицы с мультифильтрацией, формы проверки коннекторов с мгновенной диагностикой ошибок подключения, наглядные графики и цветовая индикация статусов систем).

## 6. Этапы разработки и сдачи работ

1. **Проектирование и дизайн:** сбор детальных требований, разработка прототипов (Figma) для клиентской части, дашбордов и Центра управления, утверждение дизайн-макетов и спецификаций двустороннего API для интеграции с AD и 1С.

2. **Разработка ядра, коннекторов и Центра управления:** настройка окружения и S3-хранилища, разработка менеджера внешних коннекторов и серверов в Админ-панели (AD/LDAPS, SSO, 1С, SMTP, S3), реализация синхронизации пользователей и иерархии руководителей из AD/1С, управление ролями, аудит и брокер real-time уведомлений.

3. **Разработка контентных и справочных модулей:** Пользовательский дашборд (Главная страница), Новости, Фотогалерея корпоративных мероприятий, Меню кафе и ресторана, Сотрудники, Дни рождения, информационные страницы Общих сервисов.

4. **Разработка сервисных и коммуникационных модулей:**

   * Двусторонняя интеграция с 1С, контур согласования отпусков по иерархии руководителей и конструктор маршрутов в Центре управления.

   * Собственная подсистема управления и бронирования переговорных комнат (с рабочим местом Редактора переговорных).

   * Подсистема оповещений и персональных сообщений пользователям.

5. **Тестирование и опытная эксплуатация:** нагрузочное и функциональное тестирование, проверка отказоустойчивости коннекторов и маршрутов согласования, исправление ошибок, наполнение первичным контентом.

6. **Ввод в промышленную эксплуатацию:** передача документации (руководство пользователя, руководителя, редактора и администратора) и исходного кода.
